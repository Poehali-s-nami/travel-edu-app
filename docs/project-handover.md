# Передача и эксплуатация PSN HUB

Актуально на 23 ноября 2026 года.

## 1. Назначение

PSN HUB — закрытая платформа для обучающих материалов, базы знаний, программ,
назначений группам и фиксации прогресса сотрудников.

Основные адреса:

- production: `https://psnhub.kz`;
- API: `https://api.psnhub.kz`;
- репозиторий: `https://github.com/Poehali-s-nami/travel-edu-app`;
- внешний календарь: `https://learningagenda.netlify.app`.

## 3. Рабочий стек

- Next.js 15, React 19, TypeScript;
- Tailwind CSS, Lucide Icons, Framer Motion;
- Cloudflare Pages для frontend;
- Cloudflare Worker для API и фоновых задач;
- Cloudflare D1 (SQLite) для каталога и нормализованных копий;
- Firebase Authentication для паролей и ID token;
- Firestore для канонических профилей, импорта и части транзакций;
- GitHub как единственный источник исходного кода.

Собственного сервера нет. Данные обрабатываются зарубежными облачными сервисами.
При изменении требований по локализации данных архитектуру необходимо пересмотреть.

## 4. Потоки данных

### Вход

1. Пользователь вводит CRM-логин и пароль на `psnhub.kz`.
2. Firebase Authentication проверяет пароль и выдает ID token.
3. API проверяет token и читает актуальный профиль `accessUsers` из Firestore.
4. Заблокированный, архивный или не завершивший обязательную смену пароля пользователь
   не получает каталог.

### Каталог и видимость

1. Авторизованный каталог читается из D1 через `GET /v1/catalog`.
2. Worker применяет роли, офисы и учебные группы пользователя.
3. При недоступности D1 frontend через четыре секунды использует защищенный Firestore API.
4. Активный исторический контент имеет аудиторию `everyone`; новый контент может быть
   ограничен ролями и группами администратором.

### Записи

- материалы, треки и учебные группы сначала сохраняются в Firestore, затем точечно
  синхронизируются в D1;
- подтвержденные просмотры и прогресс сохраняются в Firestore и D1 через Worker;
- `accessUsers`, `loginEvents` и `materialViews` полностью сверяются каждый день в `02:15`
  по времени Кызылорды (`21:15 UTC`);
- полный ручной перенос доступен центральному администратору через защищенный API.

## 6. Секреты и конфигурация

В Cloudflare Worker как зашифрованный secret хранится `FIREBASE_SERVICE_ACCOUNT_JSON`.
Открытые переменные Worker находятся в `cloudflare/d1-worker/wrangler.toml`.
Firebase Web API key не является паролем. Доступ к данным защищают Firebase Authentication
и Firestore Security Rules, а список authorized domains ограничивает браузерную авторизацию.

Сервисный аккаунт `psn-hub-d1-reader@travel-edu-app.iam.gserviceaccount.com` используется
Worker для серверного чтения и записи прогресса. Его роль должна оставаться минимально
необходимой (`Cloud Datastore User`); расширение до Owner или Editor запрещено.

JSON-ключ сервисного аккаунта:

- не хранится в репозитории;
- не пересылается в чатах и почте;
- заменяется при подозрении на утечку или смене ответственного;
- после ротации обновляется в Cloudflare secret, а старый ключ удаляется в Google Cloud.

## 7. Публикация

### Frontend

Коммит в `main` автоматически запускает Cloudflare Pages. После публикации проверить:

1. статус deployment `Active`;
2. `https://psnhub.kz` возвращает HTTP 200;
3. вход тестового пользователя;
4. наличие материалов и треков;
5. отсутствие ошибок в консоли браузера.

### Worker

```powershell
cd cloudflare/d1-worker
npm ci
npm test
npm run check
npm run deploy
```

В результате deploy должны отображаться `api.psnhub.kz (custom domain)` и
`schedule: 15 21 * * *`.

### Firestore rules

```powershell
npx firebase-tools login
npx firebase-tools use travel-edu-app
npx firebase-tools deploy --only firestore:rules
```

## 8. Регулярные операции

### Еженедельный импорт

Импорт выполняется в админке PSN HUB. Используется полная CRM-выгрузка и новый временный
пароль. Подробности: `docs/user-import.md`.

После импорта проверить:

- количество подтвержденных и пропущенных пользователей;
- отсутствие незавершенной точки продолжения;
- вход одного пользователя с новым временным паролем;
- вход пользователя с ранее установленным личным паролем;
- сверку Firestore и D1 в админке.

### Ежемесячная проверка

- владельцы и 2FA во всех сервисах;
- успешность Cloudflare Pages и Worker;
- журнал scheduled sync;
- совпадение Firestore и D1;
- отсутствие старых сервисных ключей;
- возможность восстановить доступ из корпоративного менеджера паролей.

## 9. Резервирование и восстановление

D1 является рабочей копией, но не заменяет отдельную резервную копию Firestore.
Наличие автоматического экспорта Firestore в отдельное хранилище сейчас документально
не подтверждено и остается операционным риском.

Минимальный план восстановления:

- ошибка frontend: вернуть последний успешный Pages deployment или отменить проблемный commit;
- ошибка Worker/D1: frontend использует Firestore fallback; вернуть предыдущую версию Worker;
- расхождение D1: запустить полную синхронизацию нужной коллекции и повторить reconciliation;
- проблема входа: проверить Firebase Authentication, authorized domains и профиль Firestore;
- потеря домена: восстановить доступ у Hoster.kz, затем проверить nameserver Cloudflare;
- компрометация ключа: создать новый ключ, обновить Worker secret, проверить API и удалить старый ключ.

Удалять Firestore, Firebase Authentication или D1 без отдельного плана миграции запрещено.

## 10. Известные ограничения

- Firebase не выведен из эксплуатации;
- инфраструктура и данные находятся за пределами Казахстана;
- календарь имеет отдельный публичный адрес Netlify;
- формальный независимый backup Firestore нужно настроить и регулярно проверять;
- Pages публикуется автоматически, Worker пока публикуется вручную;
- ежедневная полная сверка добавляет около 3000 чтений Firestore в сутки при текущем объеме;
  расход нужно пересмотреть при значительном росте пользователей и журналов.
