# Перенос PSN HUB на собственный сервер

Приложение не привязано к домену: внутренние API и ссылки на материалы используют текущий адрес сайта. Для нового домена требуется только серверная настройка.

## Перед запуском

1. Установить Node.js 20 или новее.
2. Передать переменные из `.env.local.example` через защищенное хранилище окружения сервера.
3. Значение `FIREBASE_SERVICE_ACCOUNT_JSON` хранить только на сервере. Не добавлять его в Git и не использовать префикс `NEXT_PUBLIC_`.
4. Выполнить `npm ci`, `npm run build`, затем запускать приложение командой `npm start`.
5. Настроить обратный прокси (например, Nginx) на локальный порт приложения и включить HTTPS.
6. Добавить новый домен в Firebase Authentication -> Settings -> Authorized domains.
7. Опубликовать обновленные правила Firestore из `firestore.rules`.
8. Задать `NEXT_PUBLIC_CALENDAR_URL` новым адресом календаря, если календарь переносится вместе с платформой.

## Первая синхронизация пользователей

Загрузить полную CRM-выгрузку и оставить включенной архивацию отсутствующих пользователей. Старые активные аккаунты один раз получат первоначальный пароль и обязательную смену пароля. Последующие импорты не заменяют личные пароли. Заблокированные и отсутствующие в CRM пользователи архивируются, но их прогресс не удаляется.

## Проверка после смены домена

- вход администратора;
- вход обычного пользователя с первоначальным паролем;
- обязательная смена пароля;
- повторный вход с личным паролем;
- просмотр личного кабинета, названия офиса и завершенных треков;
- смена личного пароля с подтверждением текущего;
- сброс пароля сотрудника из админки с обязательной повторной сменой;
- открытие прямой ссылки на материал и обучающий трек;
- импорт полной CRM-выгрузки;
- недоступность архивированного пользователя;
- сохранение ранее завершенных материалов.
