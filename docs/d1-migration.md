## Архитектура переходного периода

- Firebase Authentication проверяет логин, пароль и ID token.
- Firestore остается основной базой до контрольного переключения.
- D1 получает точную резервную копию документов и нормализованные таблицы.
- Миграция и сверка через `psn-hub-data-api` доступны только центральному администратору.
- Авторизованный каталог Preview читается из D1. В переходный период Worker точечно читает
  актуальный профиль пользователя из Firestore перед выдачей каталога, чтобы изменения роли,
  блокировки и обязательной смены пароля применялись сразу, даже если копия D1 еще не обновлена.
- OAuth-токен сервисного аккаунта кэшируется только в памяти Worker до истечения срока действия;
  ключ и токен не записываются в D1 и не отправляются браузеру.
- Каждая страница импорта идемпотентна: повторный запуск обновляет те же записи.
- Устаревшие строки очищаются только после успешной последней страницы коллекции;
  прерванный перенос не удаляет предыдущую полную копию.

## Точечная синхронизация каталога

В тестовой ветке административные изменения материалов, треков и учебных групп выполняются
в следующем порядке:

1. интерфейс подтверждённо записывает изменение в Firestore;
2. браузер администратора отправляет Worker только название коллекции и ID изменённого
   документа;
3. Worker повторно проверяет Firebase ID token и права центрального администратора;
4. Worker сам читает этот конкретный документ из Firestore и обновляет либо удаляет его
   копию в D1;
5. результат записывается в `audit_events` как `d1LiveSync`.

Содержимое документа не принимается от браузера, поэтому клиент не может подменить данные
при синхронизации. Один запрос содержит не более 100 ссылок на документы. Импорт CRM
возвращает ID только затронутых офисных групп, поэтому повторного чтения всей коллекции для
обновления D1 нет.

Если Firestore успешно принял изменение, а D1 временно недоступен, Firestore не откатывается:
администратор видит явное предупреждение, что D1 не обновился. До повторной успешной
синхронизации переключать production на D1 нельзя. Отсутствие
`NEXT_PUBLIC_CONTENT_API_URL` полностью отключает вызовы точечной синхронизации, поэтому
текущий production продолжает работать по прежней схеме.

## Подготовленные таблицы

- `firestore_documents` — точная копия всех полей Firestore для сверки и отката;
- `access_users` — профили и состояния доступа;
- `materials`, `tracks`, `training_groups` — учебный каталог и видимость;
- `learning_progress`, `material_views` — прогресс и просмотры;
- `audit_events` — входы, действия администратора и история импорта;
- `reference_documents` — категории и системные метаданные;
- `migration_runs` — журнал миграций.

## Создание инфраструктуры

1. В Cloudflare создать D1 database `psn-hub-production`.
2. Вставить выданный `database_id` в `cloudflare/d1-worker/wrangler.toml`.
3. В каталоге `cloudflare/d1-worker` выполнить `npm ci`.
4. Выполнить `npm run db:migrate:remote`.
5. Привязать тестовый Worker к `api.psnhub.kz`, оставив `workers_dev` и `preview_urls`
   выключенными.
6. Добавить Worker secret `FIREBASE_SERVICE_ACCOUNT_JSON` командой
   `npx wrangler secret put FIREBASE_SERVICE_ACCOUNT_JSON`.
7. Выполнить `npm run deploy`.
8. Проверить `/health`, затем запустить постраничное копирование каждой коллекции.

Для каждой коллекции первый запрос отправляется без `pageToken` и `runId`. Все следующие
страницы обязаны использовать `runId` и `nextPageToken` из предыдущего ответа. Новый запуск
для другой коллекции всегда начинается без этих двух значений.

Секрет сервисного аккаунта нельзя добавлять в Git, D1 или текстовые документы.

## Порядок миграции данных

1. `materials`, `tracks`, `trainingGroups`, `videoCategories`, `catalogMeta`.
2. `accessUsers`.
3. `learningProgress`, `materialViews`.
4. `loginEvents`, `adminImpersonations`, `importHistory`.
5. Сверить счетчики через `GET /admin/reconciliation` и контрольные выборки.

## Контрольные точки перед переключением

- число документов по каждой коллекции совпадает;
- у случайной выборки пользователей совпадают CRM ID, роли, офисы и группы;
- у случайной выборки материалов совпадают видимость, архивность и состав треков;
- прогресс тестовых пользователей совпадает;
- новая D1 API проходит тесты доступа обычного пользователя и администратора;
- контрольный Preview-запрос обычного пользователя получает `GET /v1/catalog` со статусом `200`;
- Firestore не отключается и не очищается минимум один месяц после переключения.

## Откат

Пока Firestore остается основной базой, откат не требуется: D1 получает только копию. После
переключения откат выполняется изменением источника данных обратно на Firestore. Удалять данные
или правила Firestore в течение контрольного месяца запрещено.
