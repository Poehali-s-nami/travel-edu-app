# Переход PSN HUB с Firestore на Cloudflare D1

## Текущий статус

Этап 1 подготовлен в отдельной ветке. Production продолжает использовать Firebase Authentication
и Firestore. Переключение пользовательского трафика на D1 пока не выполняется.

Firebase Authentication сохраняется и после переноса данных: хеши паролей нельзя безопасно
перенести из Firebase. Пользователи продолжат входить с текущими логинами и паролями.

## Архитектура переходного периода

- Firebase Authentication проверяет логин, пароль и ID token.
- Firestore остается основной базой до контрольного переключения.
- D1 получает точную резервную копию документов и нормализованные таблицы.
- `psn-hub-data-api` доступен только администратору для миграции и сверки.
- Каждая страница импорта идемпотентна: повторный запуск обновляет те же записи.

## Подготовленные таблицы

- `firestore_documents` — точная копия всех полей Firestore для сверки и отката;
- `access_users` — профили и состояния доступа;
- `materials`, `tracks`, `training_groups` — учебный каталог и видимость;
- `learning_progress`, `material_views` — прогресс и просмотры;
- `audit_events` — входы, действия администратора и история импорта;
- `reference_documents` — категории и системные метаданные;
- `migration_runs` — журнал миграций.

## Создание инфраструктуры

1. В Cloudflare создать D1 database `psn-hub-production`.
2. Вставить выданный `database_id` в `cloudflare/d1-worker/wrangler.toml`.
3. В каталоге `cloudflare/d1-worker` выполнить `npm ci`.
4. Выполнить `npm run db:migrate:remote`.
5. Добавить Worker secret `FIREBASE_SERVICE_ACCOUNT_JSON` командой
   `npx wrangler secret put FIREBASE_SERVICE_ACCOUNT_JSON`.
6. Выполнить `npm run deploy`.
7. Проверить `/health`, затем запустить постраничное копирование каждой коллекции.

Секрет сервисного аккаунта нельзя добавлять в Git, D1 или текстовые документы.

## Порядок миграции данных

1. `materials`, `tracks`, `trainingGroups`, `videoCategories`, `catalogMeta`.
2. `accessUsers`.
3. `learningProgress`, `materialViews`.
4. `loginEvents`, `adminImpersonations`, `importHistory`.
5. Сверить счетчики через `GET /admin/reconciliation` и контрольные выборки.

## Контрольные точки перед переключением

- число документов по каждой коллекции совпадает;
- у случайной выборки пользователей совпадают CRM ID, роли, офисы и группы;
- у случайной выборки материалов совпадают видимость, архивность и состав треков;
- прогресс тестовых пользователей совпадает;
- новая D1 API проходит тесты доступа обычного пользователя и администратора;
- Firestore не отключается и не очищается минимум один месяц после переключения.

## Откат

Пока Firestore остается основной базой, откат не требуется: D1 получает только копию. После
переключения откат выполняется изменением источника данных обратно на Firestore. Удалять данные
или правила Firestore в течение контрольного месяца запрещено.
